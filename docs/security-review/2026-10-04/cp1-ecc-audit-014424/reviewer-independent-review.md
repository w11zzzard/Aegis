## Confirmed finding and recheck

**High: a supported once-encoded configured opaque credential embedded in decoded context bypassed output/audit masking.** In `backend/guards.py`, `CredentialRedactor.matches()` checked only digest equality for the entire decoded string. Sending a permitted evaluate proposal whose output contains `base64(synthetic_token + ".")` or `base64("Synthetic value: " + synthetic_token)` returned `ALLOW` and retained the reversible encoded output. An exact encoded credential correctly returned `REDACT`. The attacker/model must supply content containing a credential; this demo does not disclose an unseen service token on its own. It nevertheless violated the claimed masking boundary, and retained encoded administrator credentials could expose privileged capabilities to readers when encountered in upstream content or retained metadata. See `reviewer-http-challenges.json` and `reviewer-baseline.json`.

The implementation owner changed decoded matching to reuse the bounded credential substring scanner. Independent intermediate probes used padded punctuation, unpadded prefix and suffix, and URL-like decoded context with an administrator credential. Those variants returned `REDACT`, absent from response, detail, feed and SQLite state. An unrelated benign encoded string returned `ALLOW` unchanged. See `reviewer-encoded-after.json`. Further independent challenges reproduced the same leak in 1,584-character and exact 16,000-character encoded containers: a smaller documented candidate limit did not close the feasible bypass. See `reviewer-large-encoded-before.json` (intentional failing-before exit 1).

The final implementation extends the single decoding layer through the full 16,000-character API text ceiling while retaining each credential substring search's 32,768-comparison cap. Both larger configured-credential probes now return `REDACT`, with no recoverable output or retained state. Exact 16,000-character benign base64 and 13,868-character encoded benign prose still return `ALLOW` unchanged. See `reviewer-large-encoded-after.json` (exit 0). Other/recursive encodings and unknown arbitrary secrets remain outside the masker; that limitation is relevant to any future real model/forwarding integration. The reproduced larger-container bypass is fixed and is no longer a remaining high finding.

**Corpus ambiguity fix independently challenged.** The implementation owner's `backend/redteam.py` duplicate-key parser was tested with literal `expected` plus Unicode-escaped `\u0065xpected`. It returns sanitized HTTP503, persists status `failed` and total0, and adds `no-store`; no completed/green run is exposed. See `reviewer-final-probes.json`. The operator-controlled corpus is not a remote request field, so this integrity fix should not be described as direct unauthorized resource access.

## Negative concerns resolved and work bounds

No source change was justified. HTTP TestClient assertions exercise actual ASGI middleware/routing, not mocked decisions; they are separate from the primary agent's socket/live-browser evidence.

With every permitted credential length 32–256 configured, representative 15–16KiB opaque/encoded inputs hit exactly 32,768 SHA comparisons and conservatively mask the whole value in approximately 21–23ms including instrumentation. Ordinary short prose uses no hashes and stays intact. After the full 16,000-character candidate fix, one configured credential length requires 27,902 aggregate comparisons for an exact-limit benign encoded value in approximately 20ms; 225 configured lengths hit the 32,768 fallback and mask in approximately 21ms. The comparison quota applies per substring search, not as a globally shared counter across all encoded candidates; aggregate work is finite because API text, candidate length and configured credential cardinality are bounded. No unbounded or practically slow path was reproduced. See `reviewer-final-probes.json` and `reviewer-large-encoded-after.json`.
